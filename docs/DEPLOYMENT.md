# Production deployment

Warehouse production is split between:

- Vercel for `apps/web`
- AWS API Gateway for the public API endpoint
- AWS Lambda for the NestJS API
- Amazon RDS PostgreSQL for persistence
- AWS Secrets Manager for generated production credentials
- AWS CDK / CloudFormation for AWS infrastructure
- GitHub Actions OIDC for subsequent AWS deployments

## AWS region

Production region:

```text
eu-central-1
```

## Production database

The production PostgreSQL database is private.

It must never be configured as publicly accessible.

Only the production Lambda security group may connect to PostgreSQL port `5432`.

Production credentials are generated by AWS Secrets Manager.

Local development database credentials must never be reused in production.

## Production authentication

The production JWT access secret is generated independently by AWS Secrets Manager.

Local development credentials such as:

```text
admin@warehouse.local
worker@warehouse.local
```

must never be seeded into the production database.

`DEV_SEED_ENABLED` must remain `false` in production.

## Public registration

Public registration is disabled by default in production:

```text
PUBLIC_REGISTRATION_ENABLED=false
```

The initial production OWNER may be created during the first deployment by temporarily enabling registration.

After the OWNER has been created, the stack must immediately be deployed again with registration disabled.

## Background workers

During Step 12:

```text
OUTBOX_WORKER_ENABLED=false
DATA_JOBS_WORKER_ENABLED=false
```

Request-driven Lambda execution is not used for timer-based background polling.

Step 13 replaces these local background loops with AWS asynchronous infrastructure.

## Vercel

The Vercel project uses:

```text
Root Directory: apps/web
Production Branch: main
```

The backend URL is provided through the server-only environment variable:

```text
API_URL
```

`API_URL` should be scoped to Production.

Do not introduce `NEXT_PUBLIC_API_URL`.

## GitHub Actions

AWS deployments use GitHub OpenID Connect.

No long-lived AWS access key or secret access key is stored in GitHub.

The production GitHub Environment provides:

```text
AWS_ACCOUNT_ID
AWS_ROLE_ARN
```

These values are identifiers, not credentials.

## Production deployment order

1. Build and validate locally.
2. Authenticate locally to AWS using temporary credentials.
3. Bootstrap the AWS CDK environment.
4. Ensure the GitHub OIDC provider exists.
5. Deploy the stack temporarily with public registration enabled.
6. Invoke the migration Lambda.
7. Create the initial production OWNER.
8. Redeploy with public registration disabled.
9. Verify `/health/live`.
10. Verify `/health/ready`.
11. Verify `/auth/register` returns HTTP 403.
12. Configure the Vercel production `API_URL`.
13. Deploy the Web project.
14. Verify login through the deployed Web application.
15. Configure the GitHub `production` Environment.
16. Use the GitHub deployment workflow for subsequent deployments.
